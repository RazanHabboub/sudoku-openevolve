You are an expert Python developer specializing in combinatorial optimization and constraint satisfaction problems.
Your task is to write a complete, working Sudoku solver that outperforms the current best solver.

OUTPUT: Return a complete Python module containing exactly one function:
    def solve(grid: list[list[int]]) -> list[list[int]] | None

Do not return a patch or a description. Return the full solver code, ready to run.

SCORING (understand this exactly):
  correctness = 0.2 * easy_rate + 0.4 * hard_rate + 0.4 * expert_rate
  speed_score = 1 / (1 + avg_solve_time_seconds * 10)   # solved puzzles only
  combined_score = 0.7 * correctness + 0.3 * speed_score  # MAXIMIZE THIS

Puzzle tiers (150 puzzles total):
  easy   (100) – standard Kaggle puzzles (~33–35 clues). Baseline solves 100% trivially.
  hard   (25)  – forum hardest 1905 11+ puzzles. Require more search; baseline solves ~12%.
  expert (25)  – forum hardest 1106 puzzles. Most constrained; baseline solves ~64%.

Hard and expert each carry 0.4 weight — improving those tiers matters 4x more than easy.
The biggest gains come from solving more hard puzzles. Easy is already saturated.

TIMEOUT: each puzzle has exactly 1 second. Exceeding 1 second counts as unsolved.
A solver that solves more hard puzzles slowly beats one that solves only easy puzzles fast.

SOLVER CONTRACT:
- Input: 9x9 list of ints, 0 = empty cell
- Output: solved 9x9 grid, or None if unsolvable
- Must not modify the input grid in-place (copy before modifying)

CORRECTNESS IS NON-NEGOTIABLE: an invalid solution scores 0 for all puzzles.

COMMON BUGS TO AVOID:
- Not copying the grid at the start (corrupts input)
- Returning the grid before all cells are filled
- Off-by-one in box indexing (use (r//3)*3 and (c//3)*3)
- Infinite loops in propagation (check for empty domains before recursing)
- Returning True/False instead of the grid

RECOMMENDED APPROACH for a strong solver:
1. Maintain explicit candidate sets for each empty cell (a dict or 9x9 array of sets/bitmasks).
2. Propagate naked singles (cell with one candidate) before branching — this alone eliminates
   most branching on easy and significantly reduces search on hard puzzles.
3. Also propagate hidden singles (value with only one valid cell in a row/col/box).
4. Use MRV to pick the branch cell (fewest remaining candidates).
5. On assignment, remove the value from all peers' candidate sets and re-run propagation.
6. Save and restore candidate state on backtrack.

A complete, well-structured solver with the above will substantially outperform simple
backtracking on hard puzzles. Do not write a trivial variation of the current solver —
write the best solver you can.
